# v0.32.0 — Retro workflow optimization

Status: **Implemented.** Target version 0.32.0. Distribution-only; edits land in
core-owned files (`steps/retro.md`, `SKILL.md`) and flow to consumers via
`/ai-dlc-update`.

## Problem

The retro (Phase 5) is the largest, slowest step. In the high-volume consumer a
single retro ran ~1–2 h wall-clock with a ~10-commit tail every sprint. An audit
(three explore passes + direct file/commit reads) located four structural cost
sources and separated them from the settled scar tissue that must NOT be touched.

**Off-limits (settled, unchanged):** party-mode's 6 real subagents + byte-matched
transcript (v0.29 solo-ban), the per-phase-vs-one-batch analyst-dispatch decision
(v0.26 §2), live deferral re-verification (freshness is the point), and all
verbose rule/hook prose (LLM-consumed scar tissue). No enforcement removed; no
prose trimmed for cost.

## Four levers

### 1. Shift-left the transcript/provenance contract (biggest win)

`validate-retro-evidence.sh` enforces a transcript shape floor (`MIN_CHARS`,
`MIN_PERSONAS`, `MIN_PHASES` over a `PHASE_LABELS` allow-list) and
`validate-provenance-block.sh` an HTML-comment provenance format — both only at
the Step-5c gate. Step 2 listed the three mandatory artifacts without these
requirements, so the operator discovered them at the gate and patched the
transcript afterward. Because the provenance block cites the transcript's git
blob SHA and the validator byte-matches it, **any transcript edit invalidates the
cited SHA**, forcing a re-cite and often a provenance reformat — a multi-commit
loop every sprint (observed on S286: 08:47 cite → 08:48 add phase labels →
08:48 re-cite → 08:51 reformat).

**Fix:** Step 2 now front-loads the contract and prescribes a commit-once order —
shape the transcript to the floor *before* committing (pointing at the script as
the single source of the thresholds, not restating them), commit the transcript
alone, capture its blob SHA, write the provenance block once in the expected
HTML-comment format, and never re-touch the transcript. Step 5c is unchanged;
only *when the requirements are known* moved earlier.

### 2. Retire the `research-citations.md` phantom pointer

`steps/retro.md` (Invariant-1 example enumeration) and `SKILL.md` both named
`research-citations.md`, a file that never existed. The every-retro
relocation-pointer scan ("every pointer resolves to a live file") therefore
failed on a dangling reference, forcing consumers to carry local override files
to mask it. **Fix:** both references removed. Invariant-1 passes clean in the
distribution; consumers drop their overrides on next `/ai-dlc-update`.

### 3. Consolidate the two co-temporal Step-4 analyst dispatches

Step 4 issued two separate `analyst` dispatches at the same post-improvement
point: the rule-file-audit candidate list, and the dormancy + pointer-invariant-1
scan tables. **Fix:** one `analyst` spawn now covers both; the "Scan dispatch"
extends the rule-audit dispatch rather than adding a second round-trip. Invariants
2 and 3 stay inline `node -e` one-liners (v0.26 §3.4). This is consistent with
the per-phase model — same phase, same causal point — not a reopening of v0.26 §2
(which rejected one up-front gather for the *whole* retro).

### 4. Local + CI double-run — no structural change, one doc fix

The local Step-5c run and the CI `validate-retro-compliance.yml` re-run of the
same validators is intentional defense-in-depth (CI catches a retro PR that
skipped the local gate); consumers with no `.github/workflows/` never double-run
at all. Nothing removed. One correctness fix: Step 5c prose claimed
`validate-mandatory-rules.sh` runs `validate-provenance-block.sh`; the script
actually chains retro-evidence + cycle-commits + **retro-prereq** (+ inline
Checks 3/5/6). Corrected so the operator's model of the gate is accurate.

## Enforcement (Rule 26(c) — no new machinery)

No new gate, script, or CI. Levers 1/3/4 are edits to `retro.md` prose; Lever 2
removes dead references. The retro's existing Step-4 rule-file audit already
scans `steps/*.md` and self-checks the structural invariant every sprint.
