# v0.11.x — Auto Session Chaining, Architecture A (committed design record)

Status: **IMPLEMENTED** (branch `feat/auto-session-chaining-impl`, 2026-07-05).
Mechanics validated by 6 spikes (claude 2.1.201). A full real-skill
chained-sprint run is the recommended acceptance test before unattended use.

## 0. Implementation refinements (supersede the design where noted)

Wiring the driver against the real skill surfaced two corrections:

- **One sentinel, not two.** The operator is attached (tmux) and steers, so the
  driver only automates the handoff clear+reseed; ordinary human pause points
  (PVC, ambiguity, retro) need no `awaiting-human.txt` — they produce an idle
  with no `handoff-resume.txt`, which the driver ignores while the operator
  handles them. Dropping the second sentinel also avoids falsely stopping the
  loop when the operator types a mid-session steer.
- **The `.idle` signal is pause-flag-gated.** `ai-dlc-continue.sh` blocks stops
  by default and only *allows* them when `pipeline-paused.flag` is present. So
  the driver-signal Stop hook writes `.idle` ONLY when that flag exists (a
  genuine lead-intended pause/handoff), never on a blocked stall — it cannot
  make the driver inject mid-pipeline. `ai-dlc-continue.sh` itself is unchanged.
- **The handoff procedure now creates the pause flag** (`touch
  pipeline-paused.flag`) in addition to writing `handoff-resume.txt`. This also
  fixes a latent gap: an *auto*-handoff has no user message to set the flag, so
  without it `ai-dlc-continue.sh` would block the session-end until the
  rapid-fire backoff. Creating the flag makes both human- and auto-handoff end
  cleanly.

Files: `SKILL.md` + `gate-validation.md` (handoff steps write the sentinel +
create the flag), `core/hooks/ai-dlc-driver-signal.sh` (flag-gated),
`core/session-driver/ai-dlc-session-driver.sh` (single-sentinel loop),
`templates/settings.json.template` + `scripts/install.sh` (register the hook,
install the driver).

## 1. Decision

Keep the operator in a **live interactive session they steer normally**, and
shed context **in place with `/clear`** at each handoff — driven by a small
side **watcher** that injects `/clear` + the resume prompt. Detection is
**pushed by hooks** (no TUI scraping); injection is a **blind keystroke send**
gated by an idle signal.

Chosen over the two alternatives (both also validated, kept as modes):
- **Headless wrapper** (fresh `claude -p` per handoff): best unattended, but
  **no mid-run steering** — rejected as default because steering is frequent.
- **Manual `/clear` + paste**: zero tooling, but manual at every handoff.

Architecture A is the only option that gives **full steering + automatic
context shed** in one session.

teammates) never applies — Architecture A never resumes; it `/clear`s a
persistent session.

## 3. Components

1. **tmux session** running interactive `claude` (the operator attaches and
   steers). Transport = tmux (default); PTY is the no-install fallback (§7).
2. **Driver-signal Stop hook** (`core/hooks/ai-dlc-driver-signal.sh`) —
   additive Stop hook; on every turn end it `touch`es `_bmad-output/.driver/idle`
   and bumps `_bmad-output/.driver/turns`. This is the "agent is idle → safe to
   inject" signal. Additive to `ai-dlc-continue.sh` (hooks coexist — spike 6
   observed "running stop hooks 0/2").
3. **Skill sentinels** (rides on v0.11.0 handoff work) — the handoff procedure
   writes `_bmad-output/handoff-resume.txt` (clean resume prompt, first line
   `/ai-dlc resume`); each Rule-3 human pause point writes
   `_bmad-output/awaiting-human.txt` (one-line reason).
4. **Watcher** (`core/session-driver/ai-dlc-session-driver.sh`) — launches the
   tmux session, then loops: on (handoff sentinel present AND idle) → inject
   `/clear` + resume via tmux; on human sentinel → notify + stand down; on
   session death → exit.

## 4. Control flow

```
operator ── tmux attach ──► live claude TUI (steer freely all session)
                                   │ turn ends
      Stop hook ─push─► _bmad-output/.driver/idle , .turns      (detection)
      skill    ─write─► handoff-resume.txt | awaiting-human.txt (intent)
                                   │
watcher loop (polls files only, never scrapes):
  handoff-resume.txt + idle  → tmux send-keys "/clear"⏎ ; paste resume ⏎ ; clear idle
  awaiting-human.txt         → bell/notify, stand down (operator takes the seat)
  tmux session gone          → exit
```

Ordering is safe: skill writes the sentinel *during* the handoff turn → agent
stops → Stop hook writes `idle` → watcher sees (sentinel + idle) → injects.
The agent is idle at inject time, so keystrokes land in the input box.

## 5. Sentinel / signal protocol

| Path | Writer | Meaning |
|---|---|---|
| `_bmad-output/handoff-resume.txt` | skill handoff step | auto-continue; contents = resume prompt |
| `_bmad-output/awaiting-human.txt` | skill pause points | stop auto-injecting; human attends |
| `_bmad-output/.driver/idle` | driver-signal Stop hook | agent idle → safe to inject |
| `_bmad-output/.driver/turns` | driver-signal Stop hook | monotonic turn count (debug/liveness) |

Watcher deletes `handoff-resume.txt` and the `idle` marker after each inject so
it waits for the next genuine idle.

Multi-line resume prompt is injected with **bracketed paste**
(`tmux load-buffer` + `paste-buffer -p`) then Enter — so embedded newlines do
not submit the input early. `/clear` is a single `send-keys` line.

## 6. Integration (minimal — additive, low coupling)

- **`ai-dlc-continue.sh` needs no logic change.** The driver-signal hook is a
  *separate additive* Stop hook; ai-dlc's stall-prevention keeps working
  untouched. The only requirement is that at a genuine handoff the continue
  hook *allows* the stop (it already discriminates handoff from premature
  stall) so the turn ends and `idle` fires. Confirm it recognizes the new
  `handoff-resume.txt` sentinel as a legitimate stop.
- **Skill sentinel writes** land in the v0.11.0 handoff procedure (being
  relocated to `steps/handoff.md` per the v0.12.0 slimming spec) — one file
  write at handoff, one at each pause point. Do not build separate machinery.
- **Settings registration** (install.sh appends): the driver-signal Stop hook
  entry, alongside the existing ai-dlc hook block.

## 7. Transport: tmux (default) vs PTY (fallback)

- **tmux** — operator `tmux attach -t ai-dlc` and steers normally; watcher
  injects via `send-keys`/`paste-buffer` without intermediating input.
  Requires `brew install tmux`. **Default** — best steering ergonomics
  (attach/detach/observe).
- **PTY** — zero-dependency (spikes 5/6 used it); the driver owns the terminal
  and relays operator input. Fallback when tmux is unavailable; steering is
  slightly less direct.

## 8. Steering is preserved

The operator is in the real TUI the entire session — type, interrupt (Esc),
correct — exactly as today. The watcher only acts at handoff *idles* (agent
just stopped, operator almost certainly not mid-keystroke). Human pause points
hand the seat back via `awaiting-human.txt`. Nothing about steering changes.

## 9. Build sequence & remaining tests

1. **Now (this spec):** ship the driver (`core/session-driver/`) and signal
   hook (`core/hooks/ai-dlc-driver-signal.sh`) as validated reference tooling.
2. **On v0.11.0:** add the two sentinel writes to the handoff/pause procedures;
   register the signal hook in `install.sh` settings merge.
3. **Integration test (required before unattended trust):** one real chained
   ai-dlc sprint — `/clear` then `/ai-dlc resume` re-invokes the skill and
   re-reads the snapshot; confirm the resumed session picks up correctly and a
   teammate-heavy phase survives across a `/clear` boundary. Spikes used
   trivial prompts; the *capabilities* are proven, end-to-end skill behavior is
   not yet.
4. **Confirm** `ai-dlc-continue.sh` + the driver-signal hook coexist under the
   real settings (observed 0/2 in a scratch harness).

## 10. Risks

| Risk | Status / mitigation |
|---|---|
| TUI scraping fragility | **DESIGNED OUT** — detection is hook-pushed files (spike 6) |
| Teammates break headless | N/A here (interactive); also retired in spikes C/2 |
| `/clear` doesn't reset context | **RETIRED** (spike 5, controlled) |
| Injection lands mid-turn | Gated on `idle` (Stop hook) → agent stopped before inject |
| Multi-line resume submits early | Bracketed paste (`paste-buffer -p`) |
| Watcher injects while operator types | Only at handoff idle; operator present; low race |
| tmux not installed | `brew install tmux`, or PTY fallback (§7) |
| Real-skill resume unverified | Integration test §9.3 before unattended use |
| Trust dialog eats first input | Driver answers it (Enter=Yes) before first inject (spike 6) |
