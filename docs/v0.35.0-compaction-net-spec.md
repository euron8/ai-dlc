# v0.35.0 — Compaction as a managed net

## Problem

AI/DLC's dominant failure mode is token saturation. The rulebook responds with
context reminders (yellow/red) and a high-fidelity reset: finalize the pipeline
snapshot, hand off, `/clear`, `/ai-dlc resume`. Claude Code has its own,
independent response: auto-compaction. Until now the two never spoke.

Two consequences, both measurable.

**The involuntary net is out of position.** Claude Code compacts at
`effectiveWindow − 13000`. On a 1M model that is 987,000 tokens, while AI/DLC's
red reminder fires at 200,000. An operator who ignores red — an unattended run,
`auto_handoff_mode: off` — keeps working for 787,000 further tokens before
anything catches them. Long enough to finish a sprint entirely inside a degraded
context.

**Recovery was prose, not mechanism.** `SKILL.md` instructed the lead to read the
snapshot first after a compact. That instruction lived in the very context the
summary may have discarded, and it competed for the 5,000-token per-skill
re-attach budget. `templates/settings.json.template` wired only `PreToolUse`,
`UserPromptSubmit`, and `Stop`. Post-compact recovery was exactly as reliable as
the model's memory of a rule it might no longer hold.

## What was verified, and how

Findings below come from reading the installed Claude Code binary
(`~/.local/share/claude/versions/2.1.206`), not from documentation. Symbol names
are minified and will not survive a version bump; the behaviour they describe is
what matters.

**The knob is a window, not a percentage.** `autoCompactWindow` is a
settings.json key — zod `number().int().min(100000).max(1000000)`, described
"Auto-compact window size". It is also settable via `/config` and
`CLAUDE_CODE_AUTO_COMPACT_WINDOW` (which accepts `auto`, `400k`, `1m`, or a bare
integer, where 100–1000 are read as thousands). Resolution order is
`env > settings > clientdata > experiment > model-default`. `effectiveWindow` is
`min(setting, model max)`; the UI states this as "the minimum of this setting and
your model's maximum context window".

**The level arithmetic.** With `_Dd = 13000`, `bDd = 3000`:

| level | fires at |
|---|---|
| warn | `threshold − 20000` |
| compact | `effectiveWindow − 13000` |
| API hard block | `effectiveWindow − 3000` |

Default windows: `1e6` for 1M-capable models, otherwise `gHr = 200000`.

**There is no supported percentage knob.** `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` maps
to an internal `testPctOverride` and clamps to
`min(floor(window · pct/100), window − 13000)` — it can only lower the threshold,
never raise it. It is a test hook. `CLAUDE_CODE_MAX_CONTEXT_TOKENS` is a dead end:
it is read only when `DISABLE_COMPACT` is set, i.e. it is mutually exclusive with
compaction.

**Three breakers bound how low the window can go.**

- `prefix_overflow` — logs `fixed prefix ~N > threshold M — compaction cannot
  help` and proceeds anyway. The fixed prefix (system prompt, tool and MCP
  schemas, CLAUDE.md, re-attached skills) is what compaction cannot remove.
- `rapid_refill_breaker` — trips after 3 consecutive refills within 3 turns each
  (`xDd = 3`). It is a **terminal stop reason**, listed beside `max_turns` and
  `stop_hook_prevented`. Its message names AI/DLC's own failure mode: *"A file
  being read or a tool output is likely too large for the context window. Try
  reading in smaller chunks, or use `/clear` to start fresh."*
- failure circuit breaker — after 3 consecutive compaction failures
  (`IDd = 3`), auto-compact is skipped for the remainder of the session.

**Compaction clears read state.** On every compaction path the runtime calls
`readFileState.clear()` and deletes `loadedNestedMemoryPaths`. Every file the lead
read earlier is gone from context *and* from the harness's record of it. The
snapshot restores position; only a fresh `Read` restores the step's instructions.

## Phase 0 result: SessionStart fires on auto-compact

The whole injection design rested on one unverified assumption. It is confirmed.

`SessionStart` is emitted by `v3r(source, …)`, called from exactly one wrapper,
`rOe(source, …)`. The only source literals passed to `rOe` are `clear`, `resume`,
and `compact`. The `compact` call site sits inside `KJn()`, the function that
rebuilds post-compaction attachments — and `KJn()` is reached from **all three**
compaction paths: `compact_full`, `compact_partial`, and `reactive_compact`. The
`compact_full` call site is in the same scope as
`I3r(i ? "auto" : "manual", …)`, the auto/manual discriminator, which proves the
auto path reaches the SessionStart emitter.

`rOe` collects each hook's `additionalContexts` and pushes them as a
`hook_additional_context` message. Injection works.

Ordering on the reactive path is `KJn()` (→ SessionStart hooks) **before**
`prt()` (→ PostCompact hooks). So `ai-dlc-recover.sh` runs first and
`ai-dlc-postcompact.sh` can record whether it fired.

A live probe was attempted first and could not observe an auto-compact: a
single-shot `claude -p` run reached a peak of 101,785 input tokens with
`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=30` (nominal threshold 60,000) without
compacting. Print mode presents one user turn, and the non-reactive auto-compact
check runs at user-turn boundaries, so the probe was structurally unable to
observe the event. The static evidence above is decisive and supersedes it. The
`PostCompact` log this release ships makes the question self-answering from here
on: any entry with `recovery_injected: no` is the design failing in the field.

## The ordering invariant

Let `threshold = min(autoCompactWindow, modelMax) − 13000`, and `red` be the red
reminder from the `SKILL.md` threshold table.

```
red + MIN_SLACK  <  threshold  <  red + MAX_DRIFT
```

Defaults `MIN_SLACK = 50000`, `MAX_DRIFT = 100000`.

The **lower bound** keeps compaction from firing at or before red, so the
high-fidelity handoff always gets first refusal, and leaves the lead room to
reach a safe seam. It catches the dangerous misconfiguration: on a 200K model the
schema minimum `autoCompactWindow: 100000` yields `threshold = 87,000`, below red
(120,000). Red would never fire first, and AI/DLC's fat resident prefix would
thrash straight into `rapid_refill_breaker`.

The **upper bound** bounds the blast radius of an ignored red.

| Model | red | default window | default threshold | verdict |
|---|---|---|---|---|
| 200K | 120,000 | 200,000 | 187,000 | passes, slack 67,000 — **no change needed** |
| 1M | 200,000 | 1,000,000 | 987,000 | fails upper bound by 687,000 |

Legal band on 1M is `window ∈ (263000, 313000)`; 300,000 is the recommendation
(`threshold = 287,000`, slack 87,000).

AI/DLC does **not** write this value. The safe floor also depends on the
consumer's fixed prefix, which the skill cannot measure. It enforces the
invariant and reports.

## What ships

| File | Role |
|---|---|
| `core/hooks/ai-dlc-precompact.sh` | Steers the summarizer; flushes a mechanical sidecar. Never blocks. |
| `core/hooks/ai-dlc-recover.sh` | `SessionStart` matcher `compact`. Re-injects the snapshot as `additionalContext`. |
| `core/hooks/ai-dlc-postcompact.sh` | Instrumentation. Display-only output; writes `compaction-log.md`. |
| `core/scripts/validate-compact-window.sh` | Enforces the ordering invariant. |

All three hooks arm only when `_bmad-output/pipeline-snapshot.md` exists — the
same convention as `ai-dlc-pause.sh` and `ai-dlc-continue.sh` — so a non-AI/DLC
session in the same repo is unaffected.

Three details that are easy to get wrong:

1. **`PreCompact` stdout replaces the compaction's custom instructions.** The hook
   must echo the incoming `custom_instructions` back before appending its own, or
   a user's `/compact <instructions>` is silently discarded.
2. **`PreCompact` must not block.** It *can* (`blockedBy`), but blocking a
   compaction that fired because the context is nearly full leaves the next stop
   at the API hard block — an unrecoverable failure rather than a degraded turn.
3. **`PostCompact` cannot inject context.** Only `userDisplayMessage` survives, so
   it is instrumentation, never recovery.

The recovery injection is byte-capped (24,000 for the snapshot, 6,000 for the
sidecar, both overridable) and states the truncation rather than clipping
silently. An unbounded injection is itself a rapid-refill trigger.

## Two latent bugs fixed in passing

**Snapshot integrity checked five of six sections.** `route.md` validated
`Pipeline Position`, `Sprint Context`, `Recent Activity`, `Open Items`, and
`Locked Decisions` — but the schema (`gate-validation.md` Check 14, `SKILL.md`
Handoff Protocol) requires `Context Reminders` too. A snapshot missing it passed
integrity and resumed.

**Context-reminder fire state survives compaction.** Compaction resets the token
counter; `context_reminders_sent` and `last_*_fire_tokens` are not reset. A
recovered lead therefore believes red has already fired, and the auto-handoff
evaluation in `_gate-procedures.md` mis-decides. `ai-dlc-recover.sh` now directs
the reset explicitly. More frequent compaction would have amplified this.

## Third bug: every pause point was pressured across its own gate

Found while reasoning about the migration below; it predates this release and is
independent of compaction. It began as a Step 0a observation and turned out to be
systemic.

Rule 3 declares "exactly THREE pause points where you stop and wait for human
input" — ambiguity resolution, the Production Validation Checkpoint, and the retro
commentary prompt — and the Stop hook that *enforces* Rule 3 recognizes an
intentional pause by exactly one signal, `pipeline-paused.flag`. **None of the
three pause points set it.** Only `handoff.md:36` and `_gate-procedures.md:179`
ever did.

`route.md` Step 0a tells the lead to surface an integrity failure and "wait for
direction." Waiting is an intentional pause, and `ai-dlc-continue.sh` recognizes
an intentional pause by exactly one signal: `_bmad-output/pipeline-paused.flag`.
Step 0a never set it. Worse, the ordering guarantees the flag is absent —
`SKILL.md` requires the lead to `rm -f` the flag "before any other action" on
`/ai-dlc` invocation, because the `UserPromptSubmit` hook had just created it, and
that clearing happens before routing.

So a failed resume always ended its turn text-only with no flag, and the Stop hook
blocked it with a Rule 3 forced-continuation reason that reads, in part:

> If you have a next action but emitted text first: pair the text with the tool
> call in your next response.

For a HARD_BLOCK that pressure is harmless, because the lead genuinely has no next
action. At Step 0a the lead has an obvious next action — dispatch to
`current_step_file` — and that is precisely what the check forbids. The
continuation hook was arguing the lead across the safety gate it had just tripped.

Secondary effect: `ai-dlc-driver-signal.sh` emits `.driver/idle` only when the
pause flag is present, so an auto-chained session got no idle signal and simply
churned until the rapid-fire backoff (3 blocks within 30s each) allowed the stop.

The same hole exists at every other site where the lead ends its turn awaiting a
human. The worst is `deploy-validate.md` §6, "Wait for Human" — the production
sign-off. There the lead ends text-only, the hook blocks, and its reason argues for
pairing the text with a tool call. The next tool call in that file is §7
Post-Validation Routing: proceed to the next sprint, or to retro. The continuation
hook was arguing the lead past the human's production approval.

Terminal stops are affected too, because nothing removes the snapshot at pipeline
end — `route.md:301` archives it only at a *fresh start*. So `continue.sh`'s
"no snapshot" escape never fires, and the final turn of a retro or an
`analysis-only` run is blocked like any other.

Fix: state the contract once in Rule 3, and `touch` the flag at each of the seven
turn-end sites — `route.md` Step 0a, `deploy-validate.md` §6, `retro.md` (commentary
prompt and terminal STOP), `gate-validation.md` Check 2 HARD_BLOCK, and
`deep-codebase-analysis.md`'s `analysis-only` terminus. No new machinery; the idiom
already existed at `handoff.md:36`. With the flag set and no `handoff` marker
present, `ai-dlc-driver-signal.sh` parks the session for an operator rather than
re-injecting.

Note that `ai-dlc-continue.sh`'s block reason *does* tell the lead to set the flag
once it has already been blocked. That reactive path bounded the damage to one
wasted turn per pause — but only where the lead has no next action. At Step 0a and
at the PVC the lead has an obvious, forbidden next action, and the reason text
argues for it. The reactive contract was never sufficient there.

## Migration note

Adding `Context Reminders` to the `route.md` integrity check will FAIL a resume
against any snapshot written before that section became universal. The failure is
surfaced with the existing `archive` / `edit` / `abort` remediation prompt, not
silent. Land this between sprints, not mid-sprint.

## Scope boundary: context-mode

AI/DLC uses none of context-mode's memory layer — no `ctx_search`, no `ctx_index`
— only `ctx_execute`/`ctx_batch_execute` for output suppression. The snapshot's
six-section schema restores *position* but has nowhere to hold *rationale*: why an
approach was rejected, what error was already hit. `ai-dlc-recover.sh` therefore
directs exactly one `ctx_search(sort: "timeline")` call in the recovery turn.

This is a gated trial under Rule 26. If it never changes a decision across a few
sprints, prune it.

The boundary is hard and already enforced: `pipeline-snapshot.md` and
`gate-log.md` are read **verbatim, never through any `ctx_*` tool**.
`ai-dlc-protect.sh` hard-blocks that path because consolidation drops directives
(Rule 23(c) limit 2). `ctx_search` is for non-schema'd rationale only. Any new
retrieval path must be added to `PROTECTED_PATTERNS` or the guarantee leaks.

## The re-attach fold, and a protocol that didn't survive its own event

Claude Code re-attaches only the first ~5,000 tokens of `SKILL.md` after a compact.
`retro.md`'s self-check asserts the `POST-COMPACT RECOVERY PROTOCOL` heading and
Rules 3, 4, and 11 fall inside that window.

The check tested the **heading**. Measuring the section revealed that the protocol
began at ~4,834 tokens and ran 566 tokens long — so roughly **400 tokens of the
post-compact recovery protocol were themselves discarded by compaction.** The
verification-turn requirements and the re-attach-budget fallback, the parts that
tell a just-compacted lead what to do, were the parts being dropped. The heading
survived; the instructions did not.

Fix, a pure reorder with no content change. `## HANDOFF PROTOCOL AND PIPELINE
SNAPSHOT` was 1,374 tokens sitting entirely above the protocol. Its two
post-compact-relevant subsections — `Living pipeline snapshot` (which the protocol
references) and `No self-scheduling skill re-entry` (a resume defense `route.md`
does not carry independently) — stay above the fold. The rest moved into a new
`## HANDOFF PROTOCOL -- TRIGGERS AND CONTEXT THRESHOLDS` below it: handoff
triggers, pending operator approvals, threshold defaults, reminder semantics,
auto-handoff, and the auto-compact ordering invariant. All are re-encountered at
the next gate through `gate-validation.md` Check 14 and `_gate-procedures.md`.

The new section keeps the `Handoff Protocol` name because eight call sites across
the step files cite `SKILL.md` Handoff Protocol `"<subsection>"`. The subsection
names are unchanged and unique, so no pointer needed rewriting.

Result:

| | before | after |
|---|---|---|
| protocol heading | ~4,834 tok | ~3,872 tok |
| protocol end | ~5,400 tok (**~400 tok dropped**) | ~4,439 tok (**fully inside**) |
| slack for future additions | 166 tok | 561 tok |

`retro.md`'s self-check now also declares the new section second-tier, and asks the
auditor to confirm the protocol's whole *body* precedes the cut — not just its
heading.

## What this does not do

It does not make compaction high-fidelity. Compaction keeps a lossy summary of
unknown content; the snapshot is a schema'd contract. These hooks narrow the gap —
deterministic re-injection instead of a remembered instruction — but the voluntary
`/clear` + `/ai-dlc resume` handoff remains strictly better, and the invariant
exists to keep it getting first refusal. Claude Code's own thrash message
prescribes the same cure.

The genuine remaining gap is the non-tmux path: without the session driver a lead
cannot `/clear` itself, so for unattended runs auto-compact is the only
involuntary reset available. Hardening it is worth doing for exactly that reason.
