# v0.29.0 — Validation sub-skills must run in independent subagents (no solo)

Status: **drafted, PR open for review (not auto-merged)** — it changes the
delegation contract AND fails in-flight solo artifacts in a live consumer
(graph S286); merge timing is the operator's call.

## Problem (observed in graph S286)

The delegation arc (Rule 24 → 28) was meant to stop the lead absorbing delegable
work inline. But S286 ran `/bmad-review-adversarial-general` and
`/bmad-validate-prd` `mode: solo` — the lead roleplaying the validation in its
own context — and the provenance block **cited Rule 20 as justification**. It was
right to: the rules permitted it. Root cause was an inconsistency:

- **Rule 28** justified permitting validation sub-skills inline by asserting *"the
  Skill call spawns real subagents … does not roleplay it."*
- **Rule 20** only *enforced* "spawn / no solo" for **party-mode**. The three
  single-voice sub-skills (`advanced-elicitation`, `review-adversarial-general`,
  `validate-prd`) have no internal spawn, so invoking them inline via Skill **is
  solo by construction** — and nothing rejected it (`validate-provenance-block.sh`
  had no solo check at all; it only required a transcript for party-mode).

Result: a single LLM adversarially reviewing an artifact its own conversation
authored (convergent, not independent) — exactly the failure the party-mode
solo-ban exists to prevent — plus the context-saturation Rule 28 targets.

## Decision (operator)

**All four validation sub-skills MUST run in real independent subagents;
`mode: solo` is forbidden for every one, enforced by rules + validator + Check 17.**

## Design

Rule 20 reframed from *"run inline"* to *"run in independent subagents."* Two
execution shapes, both `mode: subagent`:

1. **Persona-spawning (`/bmad-party-mode`)** — invoked via Skill in the lead's
   conversation; spawns persona subagents internally (role-manifest preamble).
   Unchanged.
2. **Single-voice (`advanced-elicitation`, `review-adversarial-general`,
   `validate-prd`)** — the lead dispatches the invocation to ONE spawned teammate
   (Rule 19 binding: adversarial-general → `code-reviewer`/`analyst`,
   validate-prd → `pm`, advanced-elicitation → `analyst`) that runs it in its own
   context and writes the provenance block. **This reverses the old "do NOT route
   through Agent" mandate for these three** — inline was the bug. In ai-dlc's
   autonomous mode (Rules 9/10: no mid-pipeline human dialogue) advanced-
   elicitation has no interactive loop for a subagent to break.

Rule 28's premise is now true and consistent (validation evaluation genuinely
runs in subagents; a solo run is both a Rule 20 and Rule 28 violation).

## Enforcement (teeth reach the consumer)

- **`scripts/validate-provenance-block.sh`** (core-owned; the consumer calls it
  even from its *overridden* Check 17): rejects `mode: solo` on any of the four
  tracked skills. Verified: solo → exit 1 with a Rule-20 message; subagent →
  exit 0.
- **`gate-validation.md` Check 17**: `mode` MUST be `subagent` for all four;
  `mode: solo` is a listed FAIL condition.
- **SKILL.md Rules 20 + 28**: rewritten as above.
