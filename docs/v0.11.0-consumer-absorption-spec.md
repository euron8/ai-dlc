# v0.11.0 — Consumer-absorption backport (design record)

Status: **IMPLEMENTED** in v0.11.0. Target version 0.11.0. This doc is the
design record; the shipped changes are in the `[0.11.0]` CHANGELOG entry.

## 1. Context

The graph project installed **v0.10.0 @ 2271942 (the exact HEAD)** at its
Sprint 251 and evolved the skill locally through **S281** — ~30 retro-driven
sprints. Because the install point equalled HEAD, every divergence is pure
consumer evolution on top of v0.10.0, a clean signal of what real operation
taught. Validation came from the party-mode retros (S251–S281) and commit
messages; the designated feedback log was never populated.

This release absorbs the **tech-agnostic, multi-sprint-validated** subset,
re-generalized (graph specifics stripped, Rule 18 voice, Rule 26(c)
contracts). It is deliberately selective: the consumer's `gate-validation`
grew to Check 32, but most of that bank is domain-specific (rebalancer,
subgraph, EFS/SSM, financial-display). Importing it wholesale would violate
the KISS / minimum-mechanism identity v0.10.0 established.

## 3. The auto-handoff reversal — backported as the S281-reconciled version

The plan acted on the consumer's reversal of v0.7.0's unconditional Seam-A
auto-handoff. Critically, S281 did **not** stop at the reversal: its retro
commit added **Seam E** (safe-seams now A–E) and reconciled the
`gate-validation.md` "Auto-handoff evaluation" precondition-2 so the red
threshold is **advisory-only under `safe-seam`**. Backporting only the
feature-commit SKILL.md would have recreated the exact SKILL-vs-gate-
validation contradiction S281 had to fix mid-sprint. So SKILL.md safe-seam +
Seam E + the reconciled gate-validation helper were backported **together**.

Result: mode `a` removed; `auto_handoff_mode` defaults to `off`; `safe-seam`
is seam-is-trigger (token advisory) across Seam A–E. **Trade-off:** this
re-opens the v0.7.0 prompt-cache-read-cost consideration; `safe-seam` remains
the opt-in for consumers who want automatic shedding.

## 5. Platform lessons behind the held hooks

The consumer's merge-guard and handoff resume-guard hooks are NOT backported
(v0.10.0 held guarded-merge for 0 true catches; the resume-guard fired
repeatedly false with zero true catches — precisely what Rule 26(c) says not
to add). Their validated SKILL *rules* are absorbed. The two real Claude Code
platform lessons are recorded so the value survives:

1. A hook emitting `permissionDecision: deny` on **stdout with exit 0** is
   silently bypassed when `Bash(*)` is allow-listed — the hook MUST `exit 2`.
2. Reconstruct assistant transcript text with `join("")`, not `join(" ")`,
   so streaming chunk boundaries don't corrupt marker/delimiter lines.
