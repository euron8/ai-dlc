# v0.12.0 Proposal — Resident-Context Slimming (JIT rule relocation)

Status: **Phase 1 SHIPPED** (see §9); Phase 2 pending. Target version:
0.12.0. Sequenced **after** v0.11.0
(which already edits the auto-handoff block — the single largest candidate
here, so do that relocation as part of v0.11.0's auto-handoff work and let
this spec absorb the rest).

Continues the cache/context arc (v0.5.0–v0.9.0). Prior versions cut the
**artifact** read path (Rule 23/24/25). This targets the **orchestrator
itself**: SKILL.md is the one file resident every turn of every pipeline,
and ~1/3 of it is phase-specific detail carried during phases where it is
irrelevant.

Provenance: found by evaluating the BMAD skill tree in `~/git/graph`
(`_bmad/`). BMAD never carries a single always-resident rulebook — 71
`LAZY` / 18 `Just-In-Time` markers, `nextStepFile` chaining, one workflow
loaded at a time. ai-dlc already matches BMAD's *step-level* JIT (Rules
21–25 give one-step-resident loading, resident-context discipline, analyst
offload, slice-reads). The one gap BMAD exposes: ai-dlc's **orchestrator
rulebook** is monolithic and always-on, where BMAD's phase content lives in
the phase file. This spec closes that gap without trimming any rule text.

## 1. Problem (measured on distribution SKILL.md @ v0.10.0)

`core/skills/ai-dlc/SKILL.md` = **38.4 KB ≈ 9,600 tok** (chars/4 est,
±15%), resident for the entire pipeline. A large fraction is
**phase-specific procedure/template detail** that only fires at one seam
yet occupies the window on every turn:

| Segment | Size | Relevance |
|---|---|---|
| Lines 1–479 (Rules 1–13 + handoff + post-compact) | ~5,650 tok | critical set; sits at the 5K re-attach boundary |
| Lines 480–803 (Rules 14–26 + init) | ~3,954 tok | "less time-critical" per the file's own line 484 |

The skill **already** encodes a two-tier resident model: line 484 states
Rules 14–26 "may sit past the 5K token boundary that Claude Code re-attaches
after compact." The relocation axis exists; this spec acts on it.

Top pain point context: the dominant failure mode is **token saturation**
(window exhaustion → compaction churn), not spend. Prompt-cache (v0.6.0/1h
TTL) already amortizes the *dollar* cost of resident text — but cached
tokens still occupy the window. Fewer baseline-resident tokens = more
headroom before compaction.

## 2. The scar-tissue constraint (do not regress)

ai-dlc rule verbosity is deliberate scar tissue (each rule patched an
observed failure). **This spec MUST NOT trim, soften, or delete any rule
text.** The mechanism is **relocation, not reduction**: the verbose body
moves verbatim to a JIT reference file loaded at its seam; a one-line
pointer stays in SKILL.md. Every byte survives — it just stops occupying the
window during the ~90% of turns where its seam is not active. Same
philosophy as v0.9.0 ("move, never delete"), applied to rules instead of
artifacts.

## 3. Design principles

1. **Trigger stays, procedure moves.** The *decision* to act (when to
   handoff, when to escalate, that intensity governs cycles) stays resident.
   The *how* (the step-by-step procedure, the template, the schema) moves to
   a JIT file the resident pointer names.
2. **Relocate to the file that already owns the seam.** Prefer an existing
   step/reference that already runs at that phase over a new file (KISS,
   Rule 26). New files only where no owner exists.
3. **Never relocate correctness-resident content.** Content needed when
   context is degraded (post-compact recovery) or needed to *detect* a seam
   (handoff triggers) must stay resident — see §5.
4. **Pointer must not rot.** Each relocation leaves a `READ AND FOLLOW`-style
   pointer; the retro Rule-18 audit (`retro.md` Step 4) gains a check that
   every pointer resolves to a live file (avoid the graph
   `research-citations.md` dangling-reference regression).

## 5. Correctness-resident set — MUST stay (do not relocate)

- **POST-COMPACT RECOVERY PROTOCOL (442–479)** — needed *before* the lead
  can reliably Read anything; it is the recovery path when context was
  replaced by a summary. Must stay resident **and** within the first ~5K
  tokens (Claude Code's re-attach budget). Relocating it defeats itself.
- **Handoff triggers (Rule 2)** — the lead must *detect* the handoff seam
  from resident text; only the procedure body (§4 row 2) relocates.
- **Always-on cross-cutting rules:** Rule 3 (never stall / 3 pause points /
  tool-call-first), Rule 4 (no skip), Rule 11 (interpretation preamble —
  fires per user message), Rule 21 (READ AND FOLLOW is a Read call), Rule 22
  (pause resume re-read), Rule 23 (resident-context discipline — the
  meta-rule), Rule 26 (KISS identity), and INITIALIZATION.

## 6. Ordering invariant (new, load-bearing)

Because Claude Code re-attaches only the **first ~5K tokens** of the skill
after compact, relocation MUST preserve two orderings:
1. POST-COMPACT RECOVERY stays inside the first 5K tokens.
2. After relocation, re-verify the critical set (correctness-resident +
   always-on) still fits under 5K; the freed ~2.3K of early-set headroom
   should be spent on keeping critical rules early, not backfilled with tail
   detail.

Add a check to `retro.md` Step 4 (or `gate-validation.md`): measure
SKILL.md's first-5K-token cut point and assert POST-COMPACT + Rules 3/4/11/21
land inside it.

## 7. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Relocated procedure needed at a degraded-context seam | Only the *procedure* moves; the *trigger* stays resident and names the file. One Read at the seam < carrying it every turn. Post-compact recovery never relocates (§5). |
| Pointer rots / dangles (graph's `research-citations.md` bug) | Rule-18 audit gains a resolve-every-pointer check (§3.4, §6). |
| Relocation crosses the 5K re-attach line and drops a critical rule after compact | Ordering invariant (§6) + explicit first-5K assertion. |
| New reference files proliferate (anti-KISS) | Relocate to existing seam-owners first (§3.2); new files only for handoff / rule-authoring / intensity where no owner exists. |
| Token estimate optimistic (chars/4) | Numbers are an upper bound; table/code blocks (R8, thresholds) overcount. Directional conclusion (~1/3) holds; re-measure with a real tokenizer before committing thresholds. |
| Relocation churns the cached prefix (cache-write cost) | One-time re-write on ship; steady-state is smaller-and-cached. Net win is window headroom, which cache does not provide. |

## 8. Expected impact & measurement

- **~2,000–3,600 tok (~21–38%) off the always-resident orchestrator**, every
  turn of every pipeline.
- **~2,300 tok of post-compact re-attach headroom reclaimed** — the
  correctness win (critical rules more reliably survive compaction).
- **Fewer compaction events** per long lead session (saturation is the
  driver, not spend).
- **Measure:** SKILL.md resident token count before/after; first-5K cut
  point (which rules survive re-attach) before/after; compaction events per
  session on a real sprint; that no relocated pointer dangles.
- **Honesty:** total skill bytes on disk are ~unchanged — the win is keeping
  phase detail out of the *resident* path, exactly as v0.9.0 kept history out
  of the *read* path.

## 9. Rollout

- **v0.11.0 (already in flight):** relocate the auto-handoff block (§4 row 1)
  as part of the auto-handoff redesign — largest single candidate, and that
  block is being rewritten anyway.
- **v0.12.0 Phase 1 — SHIPPED.** Rule 18 style guide → `rule-authoring.md`
  (`1919334`); handoff procedure → `steps/handoff.md` (`d89ceed`); snapshot
  6-section schema → gate-validation Check 14 (`b79b2b9`); Rule 20 provenance
  schema → gate-validation Check 17 (`5312b90`); pointer-resolve +
  first-5K ordering guardrails in retro Step 4 (`c5a0c30`). Measured result:
  SKILL.md 10,080 → 9,302 tok (−778 tok resident, chars/4), and POST-COMPACT
  RECOVERY pulled from ~5,142 tok (past the 5K re-attach budget) to ~4,946
  tok (inside it) — the §6 ordering invariant, now guarded every retro. Net
  is below the §4 gross estimate because pointers deliberately keep the
  trigger + mandate resident (scar-tissue preservation, §2).
- **v0.12.0 Phase 2 (more entangled) — PENDING:** Rule 8 intensity, Rule 24
  dispatch, Rule 25 mechanics, Rule 12 template — each keeps its mandate
  resident and moves only the procedure/table body. Note: the §4 row-1
  auto-handoff block is only partially relocated — the mode semantics +
  binding constraints (~600 tok) still sit resident before POST-COMPACT and
  are the largest remaining early-window candidate.
- **Config:** none needed — relocation is unconditional; the pointer + JIT
  Read replace the inline body. No behavior flag.
- **Existing installs:** takes effect on next `/ai-dlc` invocation (the
  reinstall overwrites the skill files); no migration, no state change.

## 10. Open questions

   have no existing owner (new files justified). Confirm intensity detail
   folds into `gate-validation.md` rather than a new `validation-intensity.md`
   (prefer no new file per Rule 26).
3. **Does relocating Rule 8 break the route-time intensity decision?**
   route.md Step 6 assigns `validation_intensity`; it needs the trigger
   thresholds. Keep the trigger table resident (or in route.md), move only
   the per-intensity skip enumerations. Verify no gate reads the enumerations
   from SKILL.md directly.

   sequence so v0.11.0's Rule 20/24 text changes land first, then this spec
   relocates the settled body. Do not relocate a rule mid-edit.
