# v0.9.0 Proposal — Artifact-Size Discipline & Slice-Reads

Status: **IMPLEMENTED** in v0.9.0 (this doc is the design record). Open
questions resolved (§11). Target version: 0.9.0.
Follows the cache-cost arc (v0.5.0–v0.8.0). This is the dominant lever
found: it targets ~10x more tokens than all prior versions combined.

## 1. Problem (measured in a real consumer, ~/git/graph, ~224 sprints)

The living planning artifacts grow **without bound**, and the skill
*mandates* it:

| Artifact | Size | Driver |
|----------|------|--------|
| `prd.md` | **393k tok** (12.3k lines, 135 per-sprint scope sections) | `research-requirements.md:45` "Do not rewrite existing requirements" → append forever |
| `product-brief.md` | **329k tok** | `discovery.md:65` "Do not rewrite existing content" |
| `carry-over-backlog.md` | **224k tok** (1,430 items, 103 resolved-in-place) | items marked CLOSED inline, never archived |
| `gate-log.md` | **103k tok** | append + **full re-read** to verify last entry; no rotation |

Worst single instruction — `carry-over-evaluation.md:32`: **"Read in
full: product-brief.md, prd.md, carry-over-backlog.md"** = **~946k
tokens in one step**, ~5x the lead's 200k window. Cannot be held →
forces repeated compaction → read *and* turn explosion. `pm.md:42`
reads PRD+brief whole. `gate-validation.md:301` re-reads the entire
103k gate-log just to confirm the last line appended.

No general artifact-size rule exists. The only bounding anywhere is the
snapshot's "keep last ~10 Recent Activity entries" (`retro.md:356`).

## 2. The scar-tissue constraint (do not regress)

"Do not rewrite existing requirements" is a **fidelity guard** — it
patched the agent dropping/altering requirements during updates. The
fix MUST preserve that no-loss guarantee. The design is **supersede
with history preservation**, never "allow rewrite":

- Nothing is ever deleted. Superseded or historical content is **moved**
  to a history/archive file, verbatim.
- The live file holds **current consolidated state only**.
- A no-loss check verifies `live ∪ history ⊇ prior content` before the
  old version is dropped from live.

## 3. Design principles

1. **Current-state live + history archive.** The live artifact is what
   is *currently true*, consolidated and deduplicated. Historical
   narrative (per-sprint scope framing) and superseded versions live in
   `*-history.md` / `*-archive.md` (files that already exist in the
   consumer but are unmanaged by the skill).
2. **Move, never delete.** Bounding = relocation, not loss.
3. **Slice, never "in full."** Sectioned artifacts are read by the
   relevant section, not whole (Rule 23(b)).
4. **Rotate append-only logs** at epoch/sprint boundaries.

## 4. Scope, sequenced

### Phase 1 — safe mechanical wins (no fidelity risk)
- **A. Slice-reads.** Replace every "read in full" of a mega-artifact
  with a sectioned read. The PRD is cleanly sectioned (144 H2s);
  callers read the relevant scope section. Pairs with v0.8.0: the
  analyst reads sliced, returns a digest; the lead never whole-reads.
  - `carry-over-evaluation.md:32` — drop "in full"; the analyst reads
    the relevant backlog items + the matching PRD/brief sections.
  - `pm.md:42` — read the scope-relevant PRD/brief sections, not whole.
- **B. gate-log tail-verify + rotation.**
  - `gate-validation.md:301` post-write verification reads the **tail**
    (last entry), not the full file.
  - Rotate `gate-log.md` per epoch/sprint into
    `gate-log-archive-<epoch>.md`; the live log holds only the current
    epoch.

### Phase 2 — bounded living artifacts (needs the no-loss design)
- **C. Supersede-to-history for PRD / product-brief.** Reframe the
  "do not rewrite" rule:
  - The live PRD holds **consolidated current requirements** (functional
    + non-functional), not per-sprint scope narrative.
  - On a sprint update: integrate new requirements into the current-state
    sections; **move** the per-sprint scope/rationale narrative and any
    superseded requirement version to `prd-history.md` verbatim.
  - The bulk of today's 393k is per-sprint framing ("## Sprint 165
    Epic-CORE Kickoff…"), not live requirements — relocating it shrinks
    the live file sharply while losing nothing.
  - Same pattern for `product-brief.md` → `product-brief-history.md`.
- **D. carry-over archive sweep.** At retro close-out
  (`retro.md:226`), **move** CLOSED/DELIVERED items from
  `carry-over-backlog.md` into `carry-over-backlog-archive.md` instead
  of leaving them inline. Live backlog holds OPEN/IN-SPRINT/DEFERRED
  only.

### Phase 3 — guardrail
- **E. Artifact-size gate check.** A new gate-validation check warns
  (not blocks) when a living artifact exceeds a token threshold
  (e.g. PRD/brief > 60k, backlog > 40k), prompting a consolidation
  pass. Threshold configurable.

## 5. No-loss enforcement (the hard part of C/D)

- Supersede/move is a **cut-and-paste**: the exact bytes removed from
  live are appended to history in the same commit. Diff invariant:
  `removed_from_live == added_to_history` (modulo a relocation header).
- A consolidation that *rewrites* current-state sections (not just
  moves) MUST pass a no-loss check: every requirement ID / locked
  requirement (Rule 13) present before is present after in `live ∪
  history`. Gate-blocks on a missing requirement.
- Locked requirements (Rule 13) are never relocated out of live — they
  are by definition current.

## 6. Migration (one-time, for existing bloated consumers)

A `prd.md` already at 393k needs a one-shot consolidation:
- New step `artifact-consolidation.md` (or a retro sub-step), run once.
- An `analyst` subagent (v0.8.0) reads the bloated artifact, drafts the
  consolidated current-state live file + the relocated history file.
- The lead runs the no-loss check (every prior requirement ID accounted
  for in live ∪ history) and the Rule 20 validation before committing.
- Gated, reversible (git), analyst-drafted + lead-verified — mirrors the
  production-vs-validation boundary.

## 7. Integrity boundaries

- No-loss guarantee preserved (§2, §5) — the "do not rewrite" scar
  tissue is honored as "do not *drop*; supersede with history."
- Rule 13 locked requirements stay live, never relocated.
- Gate checks that grep the backlog (`gate-validation.md:501`, Check 10)
  must still find OPEN/IN-SPRINT items — they remain in the live file;
  only CLOSED/DELIVERED move. No gate regression.
- Slice-reads must not miss a section a gate needs — Phase 1 read-slices
  are scoped to "the relevant section(s)," and gate checks that need the
  whole file (Check 10 grep) keep reading what they need (the live file,
  now bounded).

## 8. Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Consolidation drops a requirement | Cut-and-paste move (byte-invariant); no-loss check on rewrite; gate-block on missing ID |
| Slice-read misses needed context | Slice to relevant section(s); analyst digest surfaces gaps; whole-file gate greps unchanged on the now-bounded file |
| History/archive files themselves grow | They are write-only, never read in the hot path — growth there is free (not in the lead/analyst read path) |
| Migration on a live project | One-shot, analyst-drafted, lead+Rule-20 verified, git-reversible |
| Rotation breaks gate-log verify | Tail-verify reads the live (current-epoch) log; archived epochs are not re-read |

## 9. Expected impact & measurement

- **Largest lever found.** `carry-over-evaluation` drops from ~946k to
  bounded current-state + slices. gate-log verify drops 103k → ~1k per
  gate (every gate, every sprint). Living PRD/brief reads drop from
  393k/329k toward bounded current-state.
- Also cuts **turns** — artifacts that exceed the window force
  compaction churn; bounding them removes it.
- **Measure:** live artifact token sizes before/after consolidation;
  lead+analyst cache-read during a carry-over/planning sprint; compaction
  events per session.
- **Honesty:** history/archive files still hold the bytes — total disk
  is unchanged. The win is keeping them out of the *read path*.

## 10. Rollout

- Phase 1 (A/B) ships first — safe, mechanical, immediate. No migration.
- Phase 2 (C/D) ships with the migration step + no-loss gate.
- Phase 3 (E) as the guardrail that prevents regrowth.
- Config: `artifact_size_warn_tokens` (per-artifact thresholds);
  Phase-1 slice-reads are unconditional (no flag).
- Existing installs: Phase 1 takes effect on next session; Phase 2
  requires the one-shot migration to bound already-bloated artifacts.

## 11. Open questions — RESOLVED

1. **Single consolidated PRD + section-slicing; defer sharding.** The
   bulk of the bloat is per-sprint narrative, not live requirements;
   Phase 2 relocation likely bounds it without splitting the file.
   Decision rule: consolidate, measure, shard only if the bounded live
   PRD still exceeds ~100k. Not pre-committed.
2. **Operator-invoked, guardrail-prompted.** The Phase-3 retro audit
   *warns*; the operator runs `artifact-consolidation.md` on demand.
   Auto-firing a fidelity-critical rewrite mid-pipeline is not done.
3. **carry-over-evaluation reads whole-but-bounded, NOT sliced.** It is
   cross-cutting (every item vs the whole requirement set); slicing
   risks missing a cross-reference and mis-deciding. v0.8.0 offloads the
   read to the analyst; Phase 2 bounds the files so the whole-read is
   tractable. Slicing applies only to narrow-scope reads (pm.md,
   bug-investigation).
4. **Warn thresholds:** `prd.md` 60k, `product-brief.md` 60k,
   `carry-over-backlog.md` 40k, live `gate-log.md` 25k tokens. Warn-only,
   configurable, tuned after the first consolidation.
