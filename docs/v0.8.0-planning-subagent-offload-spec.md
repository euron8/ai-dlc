# v0.8.0 Proposal — Planning-Phase Subagent Offload

Status: **IMPLEMENTED** in v0.8.0 (this doc is the design record).
Decisions taken: new `analyst` role (not `Explore`); `planning_offload`
collapsed to a single on/off flag, default `on`; all 7 steps wired; no
per-bug complexity gating. MINOR — additive.
Author session: cache-cost reduction arc (follows v0.5.0 balanced models,
v0.6.0 cache-write, v0.7.0 cache-read).

## 1. Goal

Cut the lead session's **cache-read** cost — the dominant bucket in real
telemetry (~57% cost-weighted; 86.2M read vs 3.3M write over 3–4 sessions) —
by moving read-heavy planning/analysis work off the lead and into ephemeral
subagents whose raw exploration never enters the lead's resident context.

Read cost = lead-prefix-size × lead-turns. Today the planning/analysis steps
run **100% inline in the lead**, so every file read, grep, and fetch in those
phases accumulates in the lead's prefix and is re-read every subsequent turn.

## 2. Principle

**Offload exploration; keep decisions.** A task is a good offload candidate
when it reads a large volume and returns a small distilled artifact. The
subagent does the reading in its own context; the lead's context grows only by
a short pointer + summary. The artifact lands on disk and is queried later per
Rule 23(a) (query, don't keep resident) — not re-held in the lead.

Win = (bytes the task explores) − (distilled result returned to lead).
Only high-ratio tasks qualify.

## 3. The offload pattern

```
Lead                          Analyst subagent (ephemeral, read-only)
 |  spawn(analyst, brief) ---> reads codebase / docs / web in OWN context
 |                             writes artifact to canonical disk path
 |  <-- {artifact_path,        returns ONLY a pointer + 1-paragraph summary
 |       summary, gaps}        + any blocking gaps (NOT the raw exploration)
 |  reads artifact from disk only when a decision needs it
 |  runs inline-only work (Rule 20 validation, decisions) on the artifact
```

### Subagent contract

- **Agent type:** read-only analyst. Propose a new lightweight team role
  `analyst` (model `sonnet`, effort `medium`) — read/grep/fetch only, no
  state mutation, no Agent re-spawn. Alternatively reuse the `Explore`
  subagent type where a role file is overkill.
- **Inputs (dispatch prompt):** the step's exploration scope, the canonical
  output artifact path, and a stable shared context block (per v0.6.0
  dispatch-prompt cache discipline — shared block first, per-task tail last).
- **Behavior:** explore → write the complete artifact to its canonical path →
  return.
- **Return value (the ONLY thing that reaches the lead):**
  - `artifact_path` — where the lead can read the full output on demand
  - `summary` — one paragraph: what was produced, top findings
  - `gaps` — anything the analyst could not resolve and the lead must decide
- **MUST NOT** return the raw file contents, full grep dumps, or the
  exploration trace.

### Rule 19 spawn-map addition

`dev, qa, pm, code-reviewer, analyst -> sonnet`; `architect, tea -> opus`.
(Analyst is read-only exploration — sonnet is correct.)

## 4. Scope — which steps, ranked

### Full offload (pure exploration → artifact)
| Step | Reads | Artifact | Ratio |
|------|-------|----------|-------|
| `deep-codebase-analysis` | whole codebase | `planning-artifacts/codebase-analysis.md` | very high |
| `codebase-inventory` | codebase + artifact audit | inventory output | high |
| `bug-investigation` | code, traces, repro, planning artifacts | root-cause finding | high |
| `doc-reconciliation` | all docs | drift report | high |
| `carry-over-evaluation` | prior-sprint state, backlog, prd | carry-over items | high |

### Split (offload exploration, keep authoring + validation inline)
| Step | Offload to analyst | Stays inline in lead |
|------|--------------------|----------------------|
| `discovery` | read codebase/docs/web to inform brief | brief authoring, Rule 20 validation |
| `research-requirements` | gather references for new scope | requirement authoring, validate-prd, elicitation |

### Excluded — never offload
- Orchestration / routing / gate decisions — lead must own with full state.
- **Rule 20 validation sub-skills** (party-mode, advanced-elicitation,
  review-adversarial, validate-prd) — deliberately inline for provenance;
  offloading breaks the integrity model and Check 17 byte-matched evidence.
- `stories-test-strategy`, `implementation` — already delegate (build phase).
- Anything requiring the lead's live accumulated state.

## 5. Integrity boundaries

- **Production vs validation split.** A subagent may *produce a draft artifact*;
  the lead *validates and owns it*. Validation passes (Rule 20) run inline on
  the lead AFTER the analyst returns the draft.
- **Provenance unaffected.** Validation provenance blocks
  (`SKILL_INVOCATION_PROVENANCE v1`) are emitted by the lead's inline Skill
  invocations, not the analyst. The analyst produces inputs, not validated
  outputs.
- **Protected paths.** The analyst writes only to `planning-artifacts/` (not in
  the `core-manifest.md` core set). It MUST NOT be asked to consolidate
  rule files / snapshot / gate-log (enforced by convention + the
  gate-validation Core-layer immutability check).
- **Step-fidelity untouched.** Offload changes *who reads the codebase*, not the
  READ AND FOLLOW / STEP_LOADED_TOKEN mechanics — the lead still loads and
  follows the step file verbatim; it just dispatches the heavy reading.

## 6. Per-step change shape

Each offloaded step file gains an early section:

> **Exploration dispatch.** Spawn an `analyst` subagent (Agent tool,
> `model: sonnet`, read-only) with the exploration scope and the canonical
> artifact path. The analyst writes `<artifact>` and returns a pointer +
> summary + gaps. Do NOT perform the exploration inline. After the analyst
> returns, [continue with the step's inline authoring/validation sections].

Split steps gain the same dispatch for the *gathering* sub-steps only, with the
authoring + Rule 20 validation sub-steps explicitly marked inline.

## 7. Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Subagent output is lossy | Only exploration is offloaded; lead validates the artifact; decisions stay inline |
| Lead loses fine-grained recall | Artifact on disk; lead re-queries disk per Rule 23(a) rather than holding it resident |
| Spawn = cold cache write | Write is the cheap bucket; saving is in reads; v0.6.0 dispatch discipline reuses shared prefix across spawns |
| Provenance drift | Validation stays inline; analyst produces inputs only |
| Analyst over-returns (defeats the win) | Contract caps the return to pointer+summary+gaps; raw content forbidden |
| Continuity loss (Problem C) | Planning context is not the monitoring-continuity asset (that's build/deploy); offload keeps the lead leaner entering the phases where continuity matters |

## 8. Expected impact & measurement

- Directionally cuts lead read tokens during planning/analysis phases — the
  size of the win scales with each step's read volume (codebase analysis is the
  biggest). Magnitude unproven without per-phase telemetry.
- **Measure:** compare lead cache-read tokens across a brownfield sprint
  (heavy `deep-codebase-analysis`) before vs after. Per-phase breakdown if the
  harness exposes it; otherwise total cache-read per session on comparable
  sprints.
- **Honesty:** most cache-read volume is caching working as intended (~10x
  cheaper than uncached). This shaves the genuinely-avoidable slice (raw
  exploration the lead never needed resident), not the inherent cost.

## 9. Rollout

- Config `planning_offload_mode` in SKILL.md Handoff/Execution section:
  - `off` — all planning inline (current behavior).
  - `analysis-only` (proposed default) — full-offload steps dispatch an
    analyst; split steps stay inline.
  - `full` — full-offload + split-step gathering dispatched.
- Ship `off`-compatible: existing installs unaffected until they opt in or
  adopt the new default on a fresh install.
- New `analyst` team role file + Rule 19 spawn-map entry + per-step dispatch
  sections + CHANGELOG + VERSION 0.8.0.

## 10. Open questions

1. New `analyst` role file vs reuse `Explore` subagent type? (Role file gives a
   model binding + Rule 19 consistency; Explore is zero-maintenance.)
2. Default `analysis-only` on new installs, or ship `off` and let operators opt
   in after measuring?
3. Should `bug-investigation` offload be gated on bug complexity (cheap bugs
   don't justify a spawn)?
4. Does the split for `discovery`/`research-requirements` add enough win to
   justify the added step complexity, or start with the 5 full-offload steps
   only?
