# The Sonnet-lead A/B — measured on graph S291

**Status:** measurement complete, fixes deferred to a follow-up.
**Arm:** graph @ v0.69.0 (`b2cc5a3`), sprint 291, lead session `5edad04e` on
`claude-sonnet-5`. Measured live, mid-sprint, 2026-07-16.
**Harness:** `scripts/ab-lead-model.js` (`--graph`, `--json`, `--self-test`).

v0.62.0 shipped the escalation and explicitly deferred this: *"the A/B itself
(gate-catch parity, convergence, cost) is the follow-up… needs graph on the
reclassified map — a real pull — to be representative."* Graph pulled. This is
that A/B.

## Verdict in one line

**The hybrid works and the arm is cheaper — but the escalation that makes it safe
is unenforced, and it is already silently failing for a different role.**

## 1. Is it safe? — provisionally yes, with the risk surface relocated

Four independent things had to hold, and all four did. None was assumed; each was
checked against graph's real tree, and two of my own hypotheses were falsified in
the process.

- **The escalation fires.** 7 `GATE_ADJUDICATION_VERDICT v1` files across 4
  planning gates, 2 story gates, 1 sprint-review gate.
- **The adjudicator really runs on Opus.** All 6 `gate-adjudicator-s291-*`
  dispatches carry an explicit `model: 'opus'` param. *(I initially read the
  verdicts' self-reported `adjudicator_agent_id` — which cites the **lead's**
  Sonnet session id — as evidence the lead was roleplaying the adjudicator. It
  is not; it is a cosmetic self-reporting bug. The dispatch params are ground
  truth.)*
- **It caught real defects.** `story-20260716T110017Z` returned **check 5 = FAIL,
  check 7 = FAIL** (both canonical `sprint-status.yaml` files missing story
  entries). The lead remediated and re-dispatched (`story-20260716T110808Z`, 8/8
  PASS). The escalate → FAIL → repair → re-adjudicate loop closed **on a Sonnet
  lead**. This is the single most valuable data point in the A/B: the safety net
  is not theoretical, it fired.
- **The Sonnet lead held Rule 28(c).** `gate-log.md` cleanly separates
  *"Escalated (`adjudication: llm`, adopted via Check 26 from
  gate-adjudicator-s291-planning4)"* from *"Lead-evaluated
  (`script`/`project`/`lead`)"*. No inline roleplay of an `llm` check anywhere.

**What this does not say.** The risk did not vanish; it **moved**. The escalated
checks are now Opus by construction, so the Sonnet lead's remaining surface is
*orchestration* — Rule 28: dispatch discipline, wave planning, routing, land
order, remediation. **No gate check measures orchestration.** The only available
proxies are all clean (`steering_violations` 0 vs baseline 0; Check 25
bounded-join conduct 0; Check 17 provenance self-skips consistent), but a clean
proxy is not a measurement. Orchestration quality on a Sonnet lead remains
**unmeasured**, and that is the honest residual.

## 2. Is it cheaper? — yes, and by more than the rate card

### The counterfactual is a tautology. Do not quote it.

The plan called for re-pricing S291's volumes at Opus rates. That number is
**exactly 40.0% cheaper** — and it always will be, for any input whatsoever.
Sonnet 5 ($3/$15) and Opus 4.8 ($5/$25) sit at a uniform **0.6 ratio on every
component**: input, output, and both cache multipliers (which are defined as
fractions of input). The re-price cannot return anything but 40%. It cannot be
wrong, so it cannot inform. It is a rate identity wearing a result's clothes —
the cost-analysis form of a check that cannot fire.

The operator's call to run **both** baselines is what saved this: the measured
arm is the only half that can come out either way.

### The measured arms

Priced from the `model` + `usage` fields on every assistant turn (cache read at
0.1× input, cache write at 1.25× — **cache read dominates**: the S291 lead shows
198M cache-read tokens against 1.09M output, so an output-only cost model is off
by ~10×).

| sprint | lead tier | sessions | USD | turns | dispatches | turns/disp | **USD/disp** |
|---|---|---|---|---|---|---|---|
| 289 | opus | 7 | $665.01 | 3,983 | 76 | 52.4 | **$8.75** |
| 290 | opus (+1 sonnet tail) | 6 | $894.42 | 5,586 | 121 | 46.2 | **$7.39** |
| **291** | **sonnet** | 1 | **$99.64** | 1,159 | 39 | **29.7** | **$2.55** |

The load-bearing question was **volume**: a Sonnet lead only wins if it does not
need >1/0.6 = **1.67×** the tokens to do the same work. It does not. Measured, it
uses **fewer** turns per dispatch (29.7 vs 46.2), not more — so the rate saving
is not eaten, and per unit of orchestration the arm lands at **~65% cheaper**,
well beyond the 40% rate identity.

**Confounds, stated up front rather than buried.** S291 is a **lightweight
carry-over** sprint and is **planning-phase only so far**; S289/S290 are full
sprints including implementation, whose dispatches are heavier. The map itself
changed between arms (v0.62.0 reclassification, 0.62 → 0.69). **n = 1 sprint on
the Sonnet side, still in flight.** This is a *measurement*, not a controlled
experiment, and the phase-mix confound plausibly explains a large share of the
29.7-vs-46.2 gap. The defensible claim is narrow and it is enough: **there is no
evidence of volume inflation on the Sonnet lead, and the rate saving survives.**

## 3. Three defects in the model binding

All three verified against graph's real tree. This is the follow-up's agenda.

### D1 — The `model` param is lead-improvised, not derived *(MAJOR)*

The role file's `/model` line is **documentation**; the mechanism is the `model`
param the lead hand-passes on each `Agent` call. Nothing binds them. `tea.md`
carries **no model pin at all**, yet `tea-s291-test-strategy` was dispatched
`model: 'opus'` — the lead invented a value with no source of truth. Same class
as [[ai_dlc_v0600_one_schema]]: two homes for one fact, nothing comparing them.

### D2 — An explicit param contradicts the pin *(MAJOR — certain, and it happened twice)*

```
DRIFT   remediator-s291-disc-p1     pin=claude-opus-4-8[1m]  requested=sonnet  resolved=sonnet
DRIFT   remediator-s291-prd-p1      pin=claude-opus-4-8[1m]  requested=sonnet  resolved=sonnet
DRIFT   analyst-s291-architecture   pin=claude-sonnet-5[1m]  requested=<none>  resolved=claude-opus-4-8
```

Two remediator dispatches **explicitly requested `model: 'sonnet'`** against
remediator.md's Opus pin. That undercuts v0.56.0, whose whole finding was that
repair must leave the saturated context for a fresh, more capable one (7 of 7
repair-authored claims false; the fresh adversary right every time). This is the
strongest defect the A/B found: measured, certain, repeated.

### D2b — A missing param is UNDETERMINED *(MAJOR)*

**Correction to this document's first draft.** I originally reported that a
dropped param "silently inherits the lead's Sonnet" and that *every* S291
remediator therefore ran Sonnet against an Opus pin. **Both claims were false**,
and they were mine rather than the record's. The `Agent` tool_result reports the
teammate's model config, and all four no-param S291 spawns report
**`claude-opus-4-8`** — not the lead's Sonnet. So `remediator-s291-stories-p1`
(no param) actually *matches* its pin, and real drift is **3, not 5**.

What replaces it is worse, not better. For a spawn that *passes* a param the
field echoes the alias verbatim (`opus`); for a no-param spawn it shows a full
string (`claude-opus-4-8`). Meanwhile the Agent tool's contract says an omitted
model "uses the agent definition's model, or **inherits from the parent**". Those
disagree, the teammate leaves no transcript, and nothing downstream can settle
it. **The model a no-param spawn runs on is not knowable from the record.**

That is the real argument for denying absence: not "it inherits the wrong model"
but "no one — not the lead, not the gate, not the next reader — can say what ran".
`analyst-s291-architecture` is the measured consequence: no param, sonnet pin,
record shows opus.

### D3 — Nothing verifies the adjudicator's model *(MAJOR — hole real, trigger not yet fired)*

**Check 26 validates the verdict's envelope, coverage, and PASS/FAIL. It cannot
see who wrote it.** An explicit `model: 'sonnet'` on a `gate-adjudicator`
dispatch would produce a perfectly well-formed verdict at the right nonce with
full coverage; Check 26 would pass; the hybrid would collapse to
Sonnet-judging-Sonnet with the gate still green. The value proposition of
v0.62.0 — *"escalated to a fresh Opus context"* — rests on a parameter **no check
reads**.

**Honest scope, corrected from the first draft.** I rated this CRITICAL on the
grounds that "D2 proves the trigger already fires — the lead drops the param 8%
of the time". That was wrong twice over: all six S291 adjudicator spawns
explicitly requested opus, and a *dropped* param does not produce Sonnet anyway
(the record shows no-param resolving to opus). The hole is real and unenforced,
but it is **not firing on the adjudicator**. Its trigger is the D2 shape — an
explicit wrong tier — which is proven to occur, on remediator. MAJOR, not
CRITICAL. Still [[ai_dlc_check_cannot_fire_class]]: an invariant with no enforcer
reads exactly like one that holds.

### D4 — The arm is recorded nowhere in the repo

No `lead_model`/`arm` field exists in `GATE_METRIC v1` or the verdict envelope.
The **only** on-disk arm record is the `model` field on each assistant turn in
`~/.claude/projects/…`, outside the repo and outside every check. That is why
this harness must read transcripts, and why *"which arm ran"* is currently
**unfalsifiable from a sprint's own artifacts** — the operator's testimony is the
only in-repo evidence. An A/B whose independent variable is unrecorded is not
reproducible.

## 4. Method notes worth keeping

- **Agent-spawned teammates are not persisted to disk.** Only top-level sessions
  get a transcript. This sounds fatal to a cost A/B; it is not. The arm changes
  exactly one model — the lead's. Every teammate is pinned identically in both
  arms, so teammate cost **cancels in the delta**. The second-order effect (a
  weaker lead dispatching *more*) is still measurable as a dispatch count from
  the lead's own transcript.
- **The most important lesson is a claim of mine that was simply false.** I
  reported that a no-param dispatch inherits the lead's model, and built the
  harness, its self-test, the hook's rationale and this document's D2/D3 on top
  of it. The record said `claude-opus-4-8` all along; I never checked, because
  the assumption was plausible and the resulting table looked right. It surfaced
  only when someone asked a question about *subagents* that sent me back to the
  raw records. The self-test had **enshrined the wrong ground truth and passed**
  — the exact defect this tool exists to find, committed by the tool. Assertions
  now cite the record (`resolved=`), never an inference about it.
- **Two of my own filters nearly produced the wrong answer**, both in the
  now-familiar too-strict direction:
  1. An `isOperator` filter keyed on `/clear`, `/model`, `/compact` **deleted the
     S291 Sonnet lead** — the entire subject of the A/B — because the live lead
     issues exactly those commands at launch. The table came back all-Opus and
     looked plausible.
  2. Comparing every historical dispatch against **today's** role pins
     manufactured ~11 fake DRIFT rows for sprints 257–258, whose role files were
     different months ago. Drift is now reported for the current sprint only.
- The `--self-test` carries the 3-step proof and is **mutant-verified**:
  restoring the `isOperator` filter fails 3 of 4; crediting a no-param dispatch
  to its role pin fails the drift assertion specifically.

## 5. Recommendation

**Keep the Sonnet lead.** It is measurably cheaper with no volume inflation, it
held gate discipline, and the Opus escalation caught a real defect it was meant
to catch.

**Then close D3 before the next sprint**, because the arm's safety currently
rests on an unchecked parameter that is already being dropped elsewhere. Sketch
for the follow-up, in severity order:

1. **D3** — give Check 26 teeth on the adjudicator's model. The verdict envelope
   should carry the adjudicator's own model, self-reported *and* cross-checked,
   so a Sonnet-written verdict fails closed rather than passing green.
2. **D1/D2** — derive the dispatch `model` param from the role file instead of
   hand-passing it; a missing param must fail, not inherit. The role pin becomes
   the single source of truth, per the v0.60.0 cure.
3. **D4** — stamp `lead_model` into `GATE_METRIC v1` and the verdict envelope so
   the next A/B is answerable from the sprint's own artifacts.

Fixture note for the follow-up: dry-run any new validator against graph's **real**
verdict corpus before shipping, not just a fixture — the recurring sting is a
consumer-side check that fail-closes on the reference consumer's real artifacts.

fixes — the model binds at dispatch, where the param is observable ground truth).

## 6. Postscript — the auto-compact ceiling

Asked alongside the A/B, and it belongs here because the same cost decomposition
answers it. Graph runs `autoCompactWindow: 300000` on a 1M-capable model,
compacting 8× per sprint at 263–267K — apparently wasting 70% of the context.

Raising it is wrong three times over:

- **Cost** — cache-read is 58% of the lead's bill and scales linearly with
  resident context. The full 1M costs ~2.4× ($282 vs $117 measured).
- **Mechanics** — `effective window = min(setting, model max)`: the setting can
  only ever *lower* the threshold. A value outside `[100000, 1000000]` (e.g.
  4000000) is **silently discarded** and the model default applies — not a
  bigger ceiling, but the loss of the one you had.
- **The invariant pins it** — `validate-compact-window.sh` requires
  `red + 50000 < threshold < red + 100000`, threshold = `effectiveWindow -
  13000`. With red at 200K, `autoCompactWindow` must be ~263000–313000.
  `300000` passes; `500000` and `1000000` fail.

So 300000 is not a tuning choice that happens to be defensible — given red at
200K it is very nearly the only legal value. Leave it.

**The one argument for raising it that survives — and why it is now a
measurement.** The operator's point: the ceiling analysis above prices the
*lead*, and the lead is the one context that is fully netted (snapshot,
precompact sidecar, recovery protocol, sensor). A **teammate** has none of that,
runs in its own window, and is deliberately skipped by the sensor. A teammate
compaction is silent context loss with no recovery — a gate-adjudicator losing
its worklist mid-verdict. Headroom is worth more there than the cost model can
see, because the cost model cannot see teammates at all.

That argument is structurally sound and was **unmeasurable**: teammates leave no
transcript. So v0.70.0 stops arguing and instruments it — `SubagentStop` was a
real event wired nowhere, and `ai-dlc-subagent-probe.sh` now records every
teammate's `peak_tokens` and `compactions`. Next sprint the question is settled by
`jq -s 'max_by(.peak_tokens)' subagent-context.jsonl` against the 287000
threshold, instead of paying a certain 19% for an unquantified benefit.

The same question also surfaced a real defect it was not looking for:
`precompact.sh` and `postcompact.sh` lacked the `agent_id` gate that
`recover.sh` and the sensor carry, so a teammate compaction would have truncated
the **lead's** precompact sidecar and inflated the retro's compaction count.
Fixed in v0.70.0.
