Six were recorded in the parent plan and re-verified here; the seventh is new.

5. **`main` IS TWO SPRINTS STALE, AND THIS CLOSE-OUT IS WHERE THAT ENDS.** S300's close-out
   worked around it by cutting the next branch from HEAD; repeating that makes s302 the third

## Three inventory traps, each of which reads as a clean result

1. **A prefix-only glob undercounts, and by more than it did for s300.** `ls s301-*` gives
   **69**; `find -name '*s301*'` gives **99**. s300's gap was 81 vs 86. Control that the
   substring form is not simply over-matching: the same two forms over s300 today give **0** and
   **91** — zero for the prefix because those files are already inside `archive/s300-*`, which
   is exactly the state s301's sweep is trying to reach.
2. **`gate-metrics.jsonl` stores `sprint` as an INTEGER.** `grep '"sprint": "301"'` returns
   **0** and looks clean; `grep '"sprint": *301'` returns **75**, out of 736 rows total.
3. **NEW — grepping the corpus for `RESTART_CYCLE` returns 1, and it is a NEGATION.** The single
   hit is `s301-carry-over-evaluation-resolution-p4.md`, which says *"RESTART_CYCLE was not
   warranted — only this one passage stalled."* Control: `EXIT_CONDITION_MET` appears 22 times
   in the same corpus. **So s301, like s300, writes no `RESTART_CYCLE` record — but not for
   s300's reason**, and a close-out that greps for the token will conclude the opposite.
