# v0.33.0 — Architecture-Doc Size Discipline

Status: **IMPLEMENTED** in v0.33.0 (this doc is the design record).
Target version: 0.33.0. Direct descendant of v0.9.0 (Artifact-Size Discipline &
Slice-Reads): v0.9.0 bounded `prd.md`/`product-brief.md`/`carry-over-backlog.md`/
`gate-log.md` but never registered `architecture.md` into the same rails. This
closes that single gap.

## 1. Problem (measured in the real consumer, ~/git/graph)

| Metric | `docs/architecture.md` |
|--------|------------------------|
| Lines | 21,018 |
| Bytes | 2,023,623 |
| Tokens (≈ bytes/4) | **~506K** (~2.5× a 200K window; ~1/2 of a 1M window) |
| Structure | consolidated head ~132 lines + **124 appended "Architecture Addendum" sections** (~99% of the file) |

The doc grows because the architecture step appends a per-sprint addendum every
cycle and **never rotates history out**. Compounding it, six role/step contracts
direct spawned agents to whole-read it:

| Site | Contract |
|------|----------|
| `team-roles/dev.md:100,108` | dev Context Loading + per-task — every dev, every task |
| `team-roles/qa.md:57` | qa NFR validation |
| `team-roles/architect.md:47` | architect maintenance read |
| `team-roles/code-reviewer.md:57` | code-reviewer Context Loading |
| `steps/implementation.md:19,235` | lead Context Loading + teammate instruction |
| `steps/sprint-review-next.md:25` | sprint-review Context Loading |

One ~506K-token file loaded uncached on nearly every dispatch = the single
largest read cost in the pipeline (the v0.9.0 arc's residual).

## 2. Root cause — one artifact, absent from all four Rule 25 rails

Every *other* large living artifact is already bounded by Rule 25. `architecture.md`
alone was missing from all four rails:

1. **Rule 25(a) history mapping** (`SKILL.md`) — listed prd/brief/backlog, not architecture.
2. **Retro artifact-size audit** (`retro.md`) — measured prd/brief/backlog/gate-log, not architecture.
3. **`artifact-consolidation.md`** — handled prd/brief/backlog, not architecture.
4. **Slice-read contract (Rule 25(b))** — the six sites above whole-read with no qualifier.

Proof it was a real gap: `graph/docs/architecture-history.md` existed but was a
withered 735 lines (an unmaintained consumer improvisation), and the distribution
`core/` had **zero** `architecture-history` references — the rotation rule was
never shipped.

## 3. Scar-tissue constraint (do not regress)

Same no-loss guarantee as v0.9.0: nothing is ever deleted. Superseded content and
dated addenda are **moved** (cut, verbatim) to `architecture-history.md`; the live
file holds current consolidated state only; `live ∪ history` preserves every prior
ADR/section. The `carry-over-evaluation.md` "Read in full" exception is untouched
(bounded cross-cutting read, per v0.9.0 §11).

## 4. Design — two levers, mostly registration into existing machinery (Rule 26(b))

**Lever A — Read-side (ships now, zero consumer migration).** The six contracts
invoke Rule 25(b): read the current-state head + only the section(s) named in the
story's `architecture_refs`; never whole. Graceful degradation: `architecture_refs`
→ `docs/architecture-index.md` → `grep '^## '`, so the rule never dead-ends on a
consumer that hasn't adopted the field or index yet.

- **`architecture_refs` story-frontmatter field** (`steps/stories-test-strategy.md`
  §2b): propagated at authoring time (beside Rule 13 `LOCKED_REQUIREMENTS`) where
  the touched sections are known. `[]` is an explicit "no architecture context"
  signal, not a missing field.
- **`docs/architecture-index.md`** generated by `scripts/gen-architecture-index.js`
  (`steps/architecture.md` §4a): deterministic H2 index (heading → anchor → line →
  first-prose-line summary). No LLM, no whole-read. Measured on the 21K-line
  consumer doc: **243 lines / ~13K tokens, ~38× cheaper** than the ~506K whole-read.
  `--h3` for finer navigation.

**Lever B — Size-side (durable; registers architecture into the three unused rails).**

- **Rule 25(a)** (`SKILL.md`): add `architecture.md` → `architecture-history.md`.
- **Architecture step** (`steps/architecture.md` §2): fold net change into
  current-state, move superseded content + dated addenda verbatim to the history
  companion, instead of appending forever.
- **Retro size audit** (`steps/retro.md`): add `docs/architecture.md` at a 60k-token
  default (warn-only, Rule 25(d)).
- **Consolidation** (`steps/artifact-consolidation.md`): add architecture (manifest =
  every heading + every ADR; validate the live draft; regenerate the index; relocate
  history verbatim). Consumers run this once to collapse the existing 124 addenda —
  ~506K → consolidated head, zero loss. Operator-invoked, supervised (Rule 25(d)).

## 7. Removal condition

Retire a rail's architecture entry when the doc no longer accretes per-sprint
addenda (e.g., a naming linter or schema store supersedes the prose doc). The
slice contracts stay as long as the architecture doc is a large living artifact.
