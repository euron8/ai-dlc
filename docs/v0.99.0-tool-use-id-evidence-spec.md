# v0.99.0 spec — what `tool_use_id` actually proves

Status: **partially built in v0.99.0** — the honesty half landed; the pattern constraint
was dropped on evidence, and Option B remains open. See "Revision" at the end.

## The reported defect, and what is actually true

The graph consumer reports that the provenance reader accepts placeholder literals:
`toolu_PLACEHOLDER` satisfies the charset pattern `^toolu_[A-Za-z0-9_-]{6,}$` but is not a
real Skill-tool id. It fixed this locally with a ten-entry blocklist
(`PLACEHOLDER_TOOL_USE_IDS`) and proposes pushing it upstream.

The report is correct that a hole exists. Two things it does not say:

**The hole is far narrower than the blocklist implies.** Measured against the shipped
pattern, **8 of the consumer's 10 blocklist entries are already rejected**:

| already rejected by the pattern | actually leaking |
|---|---|
| `""`, `toolu_`, `toolu_...`, `toolu_TODO`, `toolu_XXX`, `toolu_FIXME`, `toolu_TBD`, `toolu_id` | `toolu_placeholder`, `toolu_PLACEHOLDER` |

`{6,}` already kills every short marker, and `...` fails the charset. The real leak is one
word in two casings. Adopting the blocklist upstream would ship 80% dead code — and a
hand-maintained list is the exact shape that has already cost this project twice (I8's
site table, I12's scan set, and the manifest gap I22 was written to close).

**The same hole is in the writer, and the writer's comment says otherwise.**
`stamp-story-provenance.sh:183-195` refuses to stamp when the id is invalid, and its
comment reads *"Refusing to stamp a placeholder onto the stories."* Its predicate is
`re.match(S["patterns"]["tool_use_id"], tid)` — the same charset pattern. So the writer
does not refuse placeholders either; it refuses malformed ids and believes that is the
same thing. The consumer patched only the reader, so on its tree the writer still stamps
what the reader then rejects.

That both sites already read the pattern **from the schema** is the useful part: they
share one source, so one schema change fixes both. Neither script needs a literal list.

## The larger problem the report exposes

The schema documents this field as:

> "the only non-forgeable evidence the evaluation ran in a real independent context."

Nothing in the system delivers that. `toolu_aaaaaaaa` passes the pattern, passes any
blocklist, and is not evidence of anything. A blocklist raises the cost of an *accident*
— an author copying the taught placeholder — and does nothing about forgery, deliberate
or accidental-by-habit.

This matters because the field's stated purpose is load-bearing. `validate-h2-attestation.sh`
and the gate checks treat a present, well-formed `tool_use_id` as proof the evaluation
ran. If that is a charset check wearing the word "non-forgeable," the guarantee the gate
believes it has is not the guarantee it has.

Note the contrast inside the same schema: `transcript_path` is *actually* verified.
`validate-retro-evidence.sh` step 5b runs `git cat-file -p <sha>:<path>`, so the citation
is bound to immutable content and a later edit invalidates it. One field on this block is
evidence; the other is a shape.

## The decision

Three options. They are not variations on one fix — they make different claims.

### Option A — close the accident, in the schema, and say only that

Add a `not_matching` (or equivalent) constraint to the schema's `tool_use_id` pattern
entry rejecting the placeholder stem case-insensitively, derived from the schema's own
`placeholder` string rather than enumerated. Both writer and reader pick it up with no
change to either script, because both already load the pattern from the schema.

Then **fix the two false claims**: `stamp-story-provenance.sh`'s "refusing to stamp a
placeholder" comment, and the schema's "non-forgeable evidence" doc line, which becomes
"well-formed and not the taught placeholder — a shape check, not proof of execution."

Cost: ~3 lines plus two comment corrections. Buys: the accident is caught once, in one
place, for every consumer. Does not buy: any protection against a forged id.

**Recommended**, on the grounds that it is honest about what it does. The current text is
the actual defect — a check that overstates itself is how a gate comes to believe
something no mechanism enforces, which is the same class as the fixture that had never run.

### Option B — bind the id to evidence

Make `tool_use_id` verifiable the way `transcript_path` already is: require that the id
appear in a cited transcript, and have the reader confirm it there.

This is the only option that makes the schema's existing "non-forgeable" claim true. It is
also a real design change: the reader currently opens only the schema, the extension file,
and the artifact — never a transcript — so this gives it a new dependency and a new failure
mode when the transcript is absent, rotated, or uncommitted. It likely lands as a
`required_when`-style tier (verified where a transcript exists, shape-checked elsewhere)
rather than a blanket requirement.

Do not start here without deciding whether every provenance-block-emitting context can
cite a transcript. If some structurally cannot, the tiering — not the verification — is
the hard part.

### Option C — adopt the consumer's blocklist

Rejected as specified. 80% of it is already dead, it duplicates a predicate that has a
single source, it lands in the reader only while the writer keeps the same hole, and it
is a hand-maintained list of exactly the kind this codebase has twice had to derive away.
If the accident-catch is what we want, Option A is that, done once.

## Verification, whichever option is chosen

- Assert against the **historical** value: `toolu_PLACEHOLDER` and `toolu_placeholder`
  must be rejected, and a real-shaped id (`toolu_01A9TdPqR3kMzY7bNwXvGh2L`) accepted.
- Assert the **writer and reader agree**. The current split is the actual bug shape here;
  a fixture that exercises only one of them would pass while they diverge.
- Mutation: revert the constraint and confirm the assertion fails. The existing pattern
  already rejects 8 of 10 obvious literals, so a fixture built from a naive list would
  pass against the unfixed tree — this is a case where a plausible harness is vacuous.
- Existing fixtures `check-17-counts` and `check-17-bypass` cover the reader's counts
  rules; extend rather than duplicate.

## Revision — what v0.99.0 actually built, and why it is less than Option A

Option A as written above had two halves: a schema-level constraint rejecting the
placeholder stem, and a correction of the two false claims. **Only the second half was
built.** The constraint was dropped after one more check, which this spec should have run
before recommending it:

**`toolu_PLACEHOLDER` appears nowhere in this repository.** Not in a fixture, not in a
step file, not in a role file. Every id in `core/fixtures/` is either well-formed
(`toolu_01ABCDEFGHIJKLMNOP`) or already pattern-rejected (`toolu_`, `toolu_x`). The
literal comes from the consumer's own tree and its own habits.

So the constraint would be a mechanism guarding a case with **zero upstream instances**,
justified entirely by one consumer's report — which is the profile of the over-built
candidates this project has repeatedly shipped and then had to retire. The KISS position
applies to checks and schemas, not only to code: a rule with no demonstrated upstream
instance is speculative, and the consumer can keep its narrow local guard until upstream
has evidence of its own.

It also would not have helped much. It stops `toolu_PLACEHOLDER` and does nothing about
`toolu_aaaaaaaa`, so a reader that trusts it is in exactly the position this spec objects
to — trusting a shape check as proof.

What was built instead is the part that is true regardless of any consumer's habits: two
statements in core that assert a guarantee no mechanism delivers.

- `schemas/provenance-block.json` — the `tool_use_id` doc no longer reads "the only
  non-forgeable evidence the evaluation ran in a real independent context." It now says
  the field is checked for shape only and is not proof the evaluation ran. This text is
  **rendered into the taught examples** in `team-roles/adversary.md` and `steps/retro.md`,
  so the correction reaches the agents that author these blocks, not just the schema file.
  `sync-taught-schema.sh --check` caught the stale render and gated the re-render.
- `scripts/stamp-story-provenance.sh` — the comment claiming it refuses "a placeholder"
  now states what the predicate actually does, names the shapes it cannot catch, and says
  to write "well-formed", never "real".

**Option B is unchanged and remains the only option that makes the original claim true.**
It is now also the only one left: with the constraint dropped, there is no middle path
between "shape check, honestly labelled" and "bound to evidence." That is the cleaner
choice to put to an operator.
